## 1. 冻结目标（验收底线与目标值）

| 指标 | 目标值 | 验收底线 | 测量方式 |
|---|---|---|---|
| 大屏帧率（1920×1080） | 60 FPS | **≥30 FPS** | 内置 HUD + 基准路径记录 |
| 状态数据刷新 | ≤1s | ≤1s | 状态变更到大屏上屏耗时 |
| 指令往返（局域网） | <100ms | **<200ms** | C3 实测回执 |
| 首屏加载（全厂+本期设备） | ≤5s | **≤10s**（内网） | 冷加载计时 |
| 浏览器进程内存峰值 | ≤1 GB | ≤2 GB | 开发期 HUD + 任务管理器 |

- 平板端（若保留）：低精度档，目标 ≥30 FPS（其硬件未知，按主流平板口径预估）。
- 后台端：无 3D 压力，页面操作响应 <500ms。

## 2. 量级预算推导（一期 ≤200 设备单体）

| 资源 | 预算 | 推导口径 |
|---|---|---|
| 三角面总量 | 2M–4M（含 LOD 三档叠加） | 200 设备 × 平均 5k–10k（近档）≈1–2M + 场景 0.5M + 中/远档合计 ≈1M；保守取 2–4M |
| Draw call | **≤200**（实例化后） | 静态场景合并 + 设备按类别 InstancedMesh（200 台 ≈ 20–40 个实例批次）+ 看板/UI 少量 |
| 材质数 | ≤16 共享材质 | PLAN_04 §3.2 口径 |
| 纹理显存 | ≤256 MB | 程序化材质为主；贴图按 512/1K 图集，KTX2 按需（R02） |
| 状态更新路径 | 只改实例颜色/标签可见性 | 不重建几何、不换材质程序（R01 状态驱动） |

- 参考口径：现代浏览器 WebGL 在集成显卡上可承受数百万三角面；200 台设备的场景远低于上限，**瓶颈在 draw call 与加载**而非三角面（来源见 §6）。
- 校验关系：若 C1 实测 200 实例 + LOD + 状态切换达 ≥60 FPS（本机独立显卡），目标机（未知显卡）再以 30 FPS 底线复核；不达标走 §4 降级链。

## 3. 各端预算差异

| 端 | 精度档 | 三角面预算 | 备注 |
|---|---|---|---|
| 大屏 | 全量（近档按焦点动态加载） | 2M–4M | 焦点设备加载近档高模，其余保持中/远档 |
| 平板 | 低精度（简易模型） | ≤1M | 预设固定视角，自由漫游关闭（需求 4.2 口径） |
| 后台 | 无 3D | — | 纯表单/列表 |

## 4. 性能杠杆与降级链

- 杠杆（按优先级）：① 实例化合并 draw call → ② LOD 三档 + 焦点动态升级 → ③ 静态场景合并与共享材质 → ④ 楼层分块加载（进哪层加载哪层）→ ⑤ 阴影/后处理按需开关 → ⑥ 纹理压缩与图集。
- 降级链（实测不达标时依序执行，每步记录前后数据）：
  1. 中/远档 LOD 面数减半；
  2. 近档设备面数预算下调（与 PLAN_04 联动改台账）；
  3. 关闭实时阴影（改烘焙/贴片）；
  4. 楼层强制分块加载；
  5. 目标机实测仍 <30 FPS → 升级为「降低分辨率 + 保持 30 FPS」方案并与甲方书面确认（不改报价口径，记风险 RAID）。

## 5. 测量与验收方法

- 开发期内置 HUD：FPS / 三角面 / draw call / 内存（`renderer.info` + `performance.memory`），仅开发版显示。
- 基准路径（C1 产出）：固定视角序列（全厂鸟瞰 → 厂房中层 → 单线聚焦 → 设备选中），每段 10s 记录平均/最低帧率，形成 `基准.json`，此后每次性能改动重跑对比。
- 部署验收：目标机跑同一基准路径，满足底线即性能验收通过（并入 PLAN_01 §7）。
